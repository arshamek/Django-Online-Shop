# Phase 9 – Persian and multilingual support

Persian is the default and strongest language (language code `fa`); English `en`, Arabic `ar` and Turkish `tr` are supported.

## How understanding works
Understanding is **rule-based and deterministic** (`nlu.py`, `numbers.py`, `language.py`, `vocab.py`): the message is turned into
structured filters; the language model only phrases the answer. That makes extraction testable and means a model outage
cannot break Persian budget parsing.

| Capability | Examples that are tested |
|---|---|
| Informal / formal / mixed text | «یه کتونی نایک می‌خوام» · «یه Nike کتونی مشکی سایز ۴۲ می‌خوام تا ۴ میلیون» |
| Brand transliteration | نایک → nike (plus the catalogue's own brand names, local names and aliases) |
| Characters, digits, spacing | ی/ي, ک/ك, Persian ۰-۹ and Arabic ٠-٩ digits, half-space (ZWNJ), glued `۵میلیون`; 5,000,000 / 5.000.000 |
| Number words | چهل و دو = 42 · پونصد هزار = 500,000 · یه میلیون و پانصد هزار = 1,500,000 · English "five million" |
| Budgets | «زیر ۵ میلیون تومان» (max) · «تا ۳ میلیون» · «بین ۴ تا ۶ میلیون» (range, magnitude shared) · «بالای ۲ میلیون» / «حداقل …» (min) · «حدود …» (±20 %) |
| Toman vs Rial | تومان/تومن vs ریال; Rial amounts are divided by 10 for display. Same words in English/Arabic/Turkish ("5 milyon toman altı", «أقل من 5 ملايين تومان») |
| Colloquial «تومن» | «پنج تومن» = 5 M Toman, «پونصد تومن» = 500 k Toman – reported in `assumptions` |
| Clarification | bare amounts («زیر ۵۰۰۰۰۰۰»), «۵ تومان», or foreign currency («۲۰۰ دلار», TL, AED) → the assistant asks; it never guesses |
| Sizes | «سایز چهل و دو», «size 42», «42 numara», «سایز ۴۲ تا ۴۴» (not mistaken for budgets) |
| Colours | مشکی/black/siyah/أسود … |
| Follow-ups | cheaper («ارزون‌ترشو», "cheaper", "daha ucuz", «أرخص»), colour, «فقط ترندیول», «نمشی هم بگرد», compare, availability, selection by ordinal |

Normalisation is for **matching only**; stored titles, brands, SKUs and model numbers are never modified (tested).

## Language handling
Each message is detected (script, then letters/function words): Persian-specific letters (پ چ ژ گ) and common words → `fa`,
Arabic-only letters/words → `ar`, Turkish letters/words → `tr`, otherwise Latin → `en`. Persian text with English brand names
stays Persian. A short ambiguous message («42») keeps the conversation's language. The reply uses the detected language
unless the request sets `language`; languages staff disabled fall back to Persian. Switching language mid-conversation works.

## Reply style
Persian replies come from curated templates (demo mode and fallback) or from the model under a system prompt that asks for
natural spoken-formal Persian, correct grammar, Toman amounts, no unnecessary English except brand names, no markdown.

## What has and has not been verified
* **Verified (automated, deterministic):** parsing, normalisation, language detection, budget/Toman/Rial logic, Persian
  conversations end-to-end against the mock provider, and the Persian/English/Arabic/Turkish template texts.
* **NOT verified:** the quality, grammar and tone of Persian text generated by a real language model. No real AI credentials
  were available, so no real model has been called. Do not describe Persian generation quality as verified until a Persian
  evaluation with the real model has been run (see the production blockers).
* The Arabic and Turkish templates and vocabularies are smaller than the Persian ones (Turkish/Arabic number *words* are not
  parsed; digits are) and have not been reviewed by native speakers.

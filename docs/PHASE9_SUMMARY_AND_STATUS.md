# Phase 9 – Summary and honest status

Multilingual (fa default, en, ar, tr) AI shopping assistant, **backend only**. Details: `docs/ai/`.

## 1. Implemented
* App `apps/ai_assistant/` (models, migration, services, views, URLs, admin, Celery task, management command).
* Customer API: chat, conversations (list/get/delete), recommendations, compare, purchase inquiries.
* Staff API (`accounts.ai_manage`): config, status/usage/error statistics, provider test, inquiry review.
* Unified discovery over **Maral catalogue** (live DB) and **stored Trendyol/Namshi snapshots**, with per-source status,
  conservative dedup, ranking, "why it matches" and comparison of verified attributes only.
* Prices via the **Phase 6 engine** (original / estimated / confirmed kept apart; missing costs → provisional or incomplete).
* Persian-first deterministic understanding (budgets, Toman/Rial, number words, sizes, colours, brand transliteration, follow-ups),
  language detection and fa/en/ar/tr replies.
* `AIProviderInterface` with a deterministic demo provider and an Anthropic adapter; reply validation and template fallback.
* Prompt-injection and malicious-marketplace-content defences, ownership, per-user limits, retention, audit.
* `PurchaseInquiry` workflow with mandatory staff re-checks; the assistant never creates orders, quotes or payments.
* Documentation: architecture/decisions, API contracts, frontend integration guide, setup, multilingual, limitations.

## 3. Verification facts
* **Live external search verified?** **No.** No marketplace was contacted; none of the tests use the network.
* **Real AI provider configured and tested?** **No.** No credentials existed. Everything ran in demo mode or against an injected fake
  transport. The Anthropic adapter's request/response handling is unit-tested only (`LIVE_VERIFIED = False`).
* **Persian results:** 44 deterministic parsing/normalisation/language tests plus Persian end-to-end conversations against the demo
  provider all pass. Persian text *generated by a real model* has **not** been evaluated.
* **SQL Server:** not available here; the suite ran on SQLite (the project's smoke mode). The new migration was generated and
  checked (`makemigrations --check` clean) but not applied to SQL Server.
